# M2 – Latency, "Ping" screen (2026-10-31)

The second working tab: continuous latency measurement to the gateway and internet hosts.

## Done
- **Ping screen** – a live card per target with min / avg / max RTT, jitter, packet loss and a sparkline; a detail view with a live chart; a chip showing how each target is measured (ICMP, TCP or DNS).
- **Targets** – defaults: the router (gateway), 8.8.8.8, 1.1.1.1, google.com, facebook.com, x.com. Add your own host or IP (validated, up to 20 targets); with a port the target is measured by TCP connect. Interval 0.5 / 1 / 2 / 5 s. Settings are kept across restarts (DataStore).
- **Measurement** – ICMP through the system `ping` process, TCP connect over the Wi-Fi network as a fallback, DNS lookup time measured separately for host names. Supports Android 17's local-network permission for the gateway.
- **Battery-friendly** – measuring runs only while the screen is visible; all `ping` processes are stopped when you leave it.
- **New modules** – `domain:network` (ping output parser, statistics, target validation), `core:network` (probers and latency monitor), `core:datastore` (settings and permission history).
- **Tests** – 288 unit/UI tests in total, all passing.

## Works
- Checked on a Samsung Galaxy A53 (Android 16): six targets measured over ICMP with plausible values (8.8.8.8 ≈ 9.5 ms in the app vs 9.2 ms from the shell); the processes disappear after leaving the screen; Wi-Fi off shows "not connected" and measuring resumes when it is back; an added target survives a force-stop; rotation works; no crashes.
